MOCKUPS (location: ~/Desktop/mockups/ — untracked, NOT in repo)
------------------------------------------------------
Files: BlackFriday.html, Top5.html, Blogs.html, Contact.html,
       Shops.html, Prikbord.html, "Diski Homepage Sample.html".
Self-contained "bundler" HTML (~2MB each). The page source is a
gzipped asset in <script type="__bundler/manifest">, a JSON map of
UUID -> { mime, compressed, data }, where data = base64(gzip(code)).
(NOTE: the old "<script type=text/babel src=UUID>" recipe is stale —
the current files have NO text/babel refs; decode the manifest instead.)
To read a page's design:
  - parse the __bundler/manifest JSON
  - for each entry: base64-decode data, gunzip if compressed -> source
  - the SHARED CHROME entry starts "// diski.nl — shared chrome ..."
    (tokens F/C/LBL/LINK, Mark/Wordmark/Btn/Nav/Footer)
  - the PAGE entry starts "// diski.nl — <Page name>"
A working python helper lives in the session scratchpad (extract_page.py
fallback dumps all entries by size); recreate if gone.

VERIFY TOOLING (headless screenshots + layout metrics)
------------------------------------------------------
No puppeteer in the repo, but system Chrome is at
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome".
Install puppeteer-core in the scratchpad (not the repo) and drive it.
IMPORTANT: the live R2 feeds (spotted_promotions.json, shop_registry.json)
are CORS-blocked from http://localhost — they 200 server-side but the
browser XHR fails, so the page is stuck on skeletons in local dev.
To see real cards, intercept those requests in puppeteer and re-serve
the bodies (fetched server-side) with Access-Control-Allow-Origin:*.
